# SignTools: คู่มือถอยกลับรุ่นอย่างปลอดภัย

ระบบนี้ **สร้าง ZIP เบต้าจากโค้ดฐานเสถียร 1.13.48 โดยตั้งเลขรุ่นใหม่ให้สูงขึ้น** ไม่ใช่การกดลดเลขเวอร์ชัน และไม่ใช่การ rollback Git, Worker หรือฐานข้อมูล

ฐานที่ล็อกไว้: `eb32bcd8baa9c1c4ae7834ad4fa58100324f9046` (1.13.48) ตามที่เจ้าของยืนยันว่าใช้ปุ่ม ② ได้ ไม่ใช้โค้ด 1.13.49–1.13.57 และไม่รับตัวเลือก `--from` เพื่อป้องกันเลือกฐานผิด หากจะเปลี่ยนฐานในอนาคต ต้องตรวจและให้เจ้าของยืนยันฐานใหม่ก่อนแก้สคริปต์

## ข้อห้าม

- สร้าง/ปล่อยเฉพาะ **เบต้า** สำหรับเครื่องทดสอบ ห้ามปล่อยรุ่นให้ลูกค้าโดยไม่ได้รับคำยืนยันจากเจ้าของ
- ห้ามเปลี่ยนปุ่ม ② หรือโค้ดแผงเพื่อทำ rollback นี้
- ห้ามทำงานข้อถัดไปก่อนเจ้าของลองปุ่ม ② และตัดจริงผ่าน
- สคริปต์ไม่อัปโหลด ไม่เรียก Worker ไม่ deploy ไม่ push และไม่แก้ข้อมูลใบงาน/ค่าเครื่องตัด
- ผลทดสอบตัวจำลองไม่ใช่ผลทดสอบ Illustrator, Graphtec หรือ NAS จริง

## 1. ตรวจเลขรุ่นจริงก่อนทุกครั้ง

ระบบอัปเดตใน `SignTools/js/core.js` ใช้การเปรียบเทียบตัวเลข `X.Y.Z` และเสนอให้อัปเดตเมื่อเลขบนเซิร์ฟเวอร์ **สูงกว่า** เลขในเครื่องเท่านั้น ดังนั้นถ้ารุ่นที่พังคือ 1.13.60 จะเอา ZIP 1.13.59 ไปให้อัปเดตผ่านแผงไม่ได้ ต้องสร้างรุ่นถอยกลับใหม่อย่างน้อย 1.13.61

ตรวจหน้าผู้ดูแลและเครื่องทดสอบทั้งหมด แล้วใช้เลข **สูงสุดระหว่างรุ่นที่ปล่อยอยู่กับรุ่นที่ติดตั้งจริง** เป็น `--current` ห้ามอาศัยแค่บันทึกเก่า สคริปต์ไม่ตรวจเซิร์ฟเวอร์ให้ และไม่รู้รุ่นที่เก็บอยู่นอกโฟลเดอร์ผลลัพธ์

ไฟล์ส่งต่อวันที่ 8 พฤศจิกายน 2026 ระบุเบต้า 1.13.58 ซึ่งเป็นโค้ด 1.13.48 เปลี่ยนเลขให้สูงขึ้น ตัวอย่างด้านล่างจึงใช้ 1.13.59 **เฉพาะเมื่อได้ตรวจแล้วว่าไม่มีรุ่นสูงกว่า 1.13.58** ลูกค้ารุ่นปกติถูกระบุว่าอยู่ที่ 1.12.3; บันทึกนี้ยังไม่ใช่การตรวจสถานะบนเซิร์ฟเวอร์

## 2. เตรียมเครื่องสร้าง ZIP

ใช้ Linux หรือ WSL ที่มี Bash, Git, Python 3.9 ขึ้นไป, Node.js 18 ขึ้นไป, GNU sed, zip, tar และ GNU coreutils ตัวติดตั้งใน ZIP ยังคงเป็น Windows/macOS ของฐานเดิม แต่สคริปต์สร้าง ZIP ไม่รองรับ macOS BSD sed โดยตรง

เก็บคลังโค้ดนี้ไว้ใน Git รวมถึง `rollback.sh`, `ROLLBACK.md`, `tests/panel-smoke.cjs` และ `tests/rollback-test.py` เพื่อไม่ให้งานหายเมื่อ sandbox รีเซ็ต อย่าใช้ `git reset --hard` กับสาขาที่มีงานใหม่

```bash
git fetch origin
# ไปยังสาขางาน rollback ที่เก็บสคริปต์/เทสต์ไว้ โดยไม่ทิ้งงานที่ยังไม่ commit
cd signtools-panel
bash rollback.sh --help
```

หาก Git object ของฐาน 1.13.48 ไม่มี สคริปต์จะหยุดให้ fetch ก่อน ไม่เดาและไม่ใช้ HEAD แทน

## 3. ตรวจแบบไม่สร้างไฟล์

```bash
bash rollback.sh 1.13.59 --current 1.13.58 --dry-run
```

ตรวจรูปแบบเลขรุ่น ฐานเสถียร เครื่องมือ และปลายทางที่ห้ามใช้ แต่ **ยังไม่ได้สร้าง ZIP หรือรันตัวจำลองแผง** และไม่ได้ยืนยันเลขรุ่นบน Worker รูปแบบต้องเป็นตัวเลขสามส่วน ไม่มีเลขศูนย์นำหน้า และแต่ละส่วนไม่เกิน 9 หลัก

## 4. สร้างและตรวจแพ็กเกจ

```bash
bash rollback.sh 1.13.59 --current 1.13.58

# หรือกำหนดโฟลเดอร์เก็บผลลัพธ์เอง (path สัมพัทธ์นับจากที่รันคำสั่ง)
bash rollback.sh 1.13.59 --current 1.13.58 --out /home/ubuntu/output/signtools-rollback
```

สิ่งที่สคริปต์ทำ:

1. ดึงเฉพาะ `signtools-panel/` จาก commit ฐานด้วย `git archive` ไปยังโฟลเดอร์ชั่วคราว ไม่ checkout/reset และไม่ใช้โค้ดที่แก้ค้างอยู่ใน working tree
2. เรียก `build.sh` ของฐาน 1.13.48 เพื่อเปลี่ยนเลขใน manifest และตัวติดตั้ง Windows/macOS ให้ตรงกัน
3. ตรวจ CRC, รายการไฟล์, path, executable permission และเทียบ **ทุกไบต์ของทุกไฟล์ใน ZIP** กับฐาน Git อนุญาตเพียงการเปลี่ยนเลขรุ่นใน 3 ไฟล์เท่านั้น `sticker.js`, `host.jsx` และโค้ดส่วนอื่นต้องตรงฐานทั้งหมด
4. แตก ZIP และรัน `tests/panel-smoke.cjs` กับไฟล์จาก ZIP โดยจำลอง DOM/Canvas/CEP บน Node.js หากไม่ผ่าน ไม่ส่งโฟลเดอร์ผลลัพธ์ออก
5. ส่งโฟลเดอร์ผลลัพธ์เมื่อผ่านทั้งหมด เก็บ SHA-256 และข้อมูลฐานไว้สำหรับตรวจย้อนกลับ

ค่าเริ่มต้นเก็บที่ `signtools-panel/rollback-output/rollback-v1.13.59/` ประกอบด้วย:

| ไฟล์ | ใช้ทำอะไร |
| --- | --- |
| `SignTools-v1.13.59.zip` | ไฟล์สำหรับอัปโหลดเป็นเบต้า หรือใช้ติดตั้งด้วยมือบนเครื่องทดสอบ |
| `SignTools-v1.13.59.zip.sha256` | ตรวจว่า ZIP ไม่เปลี่ยนหลังสร้าง |
| `rollback.json` | commit ฐาน เลขรุ่น ค่า SHA-256 ทุกไฟล์ และขอบเขตผลทดสอบ |
| `release-notes.txt` | ข้อความ “มีอะไรใหม่” พร้อมคำเตือนเบต้า |
| `panel-smoke.log` | ผลตัวจำลองแผง ไม่ใช่ผลเครื่องจริง |

ตรวจ checksum จากโฟลเดอร์ผลลัพธ์:

```bash
cd rollback-output/rollback-v1.13.59
sha256sum -c SignTools-v1.13.59.zip.sha256
```

สคริปต์ไม่เขียนทับโฟลเดอร์รุ่นเดิม และไม่สร้างเลขเท่ากับ/ต่ำกว่าแพ็กเกจที่มีอยู่ในปลายทางเดียวกัน ห้ามย้ายไฟล์เก่าออกเพื่อใช้เลขรุ่นซ้ำที่เคยปล่อยแล้ว หากต้องการเทสต์ซ้ำแบบไม่ปล่อย ใช้โฟลเดอร์ทดสอบปลายทางอื่น

ปลายทางมีล็อก `.rollback.lock` กันสองคำสั่งทำงานพร้อมกัน โดยปกติสคริปต์จะเก็บกวาดเอง หาก process ถูก kill แบบบังคับหรือเครื่องดับ ล็อก/โฟลเดอร์ชั่วคราวอาจเหลืออยู่ **ต้องตรวจว่าไม่มีงานสร้าง ZIP กำลังรันก่อนลบเอง** สคริปต์ไม่ลบล็อกของงานอื่นโดยอัตโนมัติ

## 5. ทดสอบระบบ rollback เอง

รันจากโฟลเดอร์ `signtools-panel`:

```bash
python3 tests/rollback-test.py
```

เทสต์ใช้คลังโค้ดจำลองชั่วคราวที่อ้างอิง Git objects เดิม ไม่ checkout สาขาที่ใช้งานอยู่ ตรวจการปฏิเสธเลขรุ่นผิด/เท่ากัน/ต่ำกว่า การไม่ทับไฟล์เดิม การไม่ใช้ working tree ที่ถูกแก้ การหยุดเมื่อ ZIP ถูกเปลี่ยนหรือ simulator ล้ม และการเก็บกวาดเมื่อเกิดข้อผิดพลาด ไม่มีการเรียก Worker/Illustrator/Graphtec

## 6. อัปโหลดเป็นเบต้า — ทำเมื่อได้รับคำสั่งให้ปล่อยแล้วเท่านั้น

การสร้างแพ็กเกจไม่ใช่การปล่อยรุ่น ขั้นตอนนี้ทำด้วยมือหรือโดยผู้ช่วยที่ได้รับคำสั่งให้ปล่อยเบต้ารุ่นนั้นแล้ว:

1. เปิด `https://signtools.organic-parmesan.workers.dev/admin` และตรวจรุ่นล่าสุดอีกครั้ง ถ้าเลขสูงขึ้นแล้ว ให้หยุดและสร้างเลขถอยกลับที่สูงกว่าใหม่
2. ใส่เวอร์ชันให้ตรงกับชื่อ ZIP และ manifest เช่น `1.13.59`
3. วางข้อความจาก `release-notes.txt` และเลือก ZIP ที่ผ่านเทสต์/ตรวจ SHA-256 แล้ว
4. **ติ๊ก “เบต้า” ก่อนกด “อัปโหลด + ปล่อย”** ตรวจกลุ่มทดสอบตามไฟล์ส่งต่อคือ 0935353555 และ 0900000000; ยังไม่ได้ตรวจว่าค่าบน Worker ปัจจุบันตรงกันหรือไม่
5. ตรวจว่ารุ่นปกติของลูกค้าไม่เปลี่ยน หากไม่สามารถยืนยันช่องเบต้าหรือกลุ่มทดสอบได้ ให้หยุด ไม่เดา
6. ปิดแท็บผู้ดูแลเมื่อทำเสร็จ

อย่าเปลี่ยน Worker หรือฐานข้อมูลเพื่อให้เลขรุ่นต่ำกว่ายังอัปเดตได้ และอย่า push tag; ระบบ rollback นี้ไม่ต้องใช้ tag

## 7. เจ้าของทดสอบ Illustrator และเครื่องตัด

ก่อนติดตั้ง ให้บันทึกงานที่เปิดอยู่ สำรองไฟล์ `.ai`/ใบงานสำคัญ และเก็บสำเนาโฟลเดอร์แผงกับข้อมูลแผงเดิมให้เรียบร้อย จากนั้นใช้เครื่องทดสอบเบต้า ไม่ใช้เครื่องลูกค้า:

- กด “เช็คอัปเดต” ตรวจว่าเลขถอยกลับใหม่ปรากฏ แล้วอัปเดต ปิด Illustrator ทั้งโปรแกรมและเปิดใหม่เพื่อหลีกเลี่ยง host.jsx/cache เก่าค้าง
- ตรวจเลขรุ่นในแผงให้ตรงกับรุ่นที่เพิ่งสร้าง
- ใช้สำเนาไฟล์งานเล็กที่เคยใช้งานได้ เลือกงาน กด ① อ่านสติ๊กเกอร์ แล้วกด **② สร้างแผ่นงาน** ตรวจ artboard, จำนวนดวง, Print/Kiss Cut/Marks และ DieCut หากเปิดใช้งาน
- ทดลองทั้งลายเดียวและหลายลาย รวมถึงชนิดงานประจำร้านโดยไม่เสี่ยงใช้ไฟล์ต้นฉบับเพียงชุดเดียว
- ใช้เศษวัสดุ/งานทดสอบ ตรวจแรงและความเร็วก่อนส่ง Graphtec แล้วตรวจมาร์ค, Kiss cut, Die cut, ตำแหน่งและผลตัดจริง
- แจ้งผลและอาการผิดปกติให้ชัดเจน หากไม่ผ่านให้หยุด อย่าเริ่มงานข้อ 1–6 ต่อ

### ถ้าอัปเดตในแผงไม่สำเร็จหรือต้องการติดตั้งสะอาด

ใช้ ZIP เดียวกันติดตั้งด้วยมือเฉพาะเครื่องทดสอบ: ปิด Illustrator ทั้งโปรแกรม แตก ZIP แล้วใช้ `install-windows.bat` หรือ `install-mac.command` ตามระบบ อย่ารันจาก ZIP โดยไม่แตกไฟล์

**ตัวติดตั้งเดิมลบโฟลเดอร์แผง SignTools และแผง ThaiFontPreview เดิมถ้ามี** เพื่อคัดลอกใหม่ ต้องสำรองก่อน ผู้ช่วยยังไม่ได้ทดสอบตัวติดตั้งบน Windows/macOS จริง

ตัวอัปเดตในฐาน 1.13.48 คัดลอกไฟล์ใหม่ทับและสำรองแผงเดิม แต่ **ไม่ได้ลบไฟล์ส่วนเกินทั้งหมดจากรุ่นที่ใหม่กว่า** จึงห้ามอ้างว่าการอัปเดตผ่านแผงทำให้โฟลเดอร์ที่ติดตั้งเหมือน ZIP ทุกไฟล์ หากสงสัยไฟล์ตกค้าง ใช้การติดตั้งสะอาดหลังสำรอง ไม่แก้ updater ในงานนี้

## ขอบเขตที่ไม่ย้อนกลับ

rollback นี้เปลี่ยนเฉพาะไฟล์แผงที่บรรจุใน ZIP ไม่คืนค่า localStorage, ไลเซนส์, ใบงาน, ไฟล์พิมพ์/ตัด, ข้อมูล NAS, ค่าที่อยู่บน Worker หรือ schema D1 หากรุ่นที่พังเคยเปลี่ยนข้อมูลเหล่านี้ ต้องวางแผนกู้ข้อมูลแยก ห้ามถือว่า ZIP แก้ให้แล้ว

บน Windows ข้อมูลระบบไลเซนส์/สำรองอัปเดตอยู่ใต้ `%APPDATA%\SignTools`; บน macOS อยู่ใต้ `~/Library/Application Support/SignTools` ตามค่าเริ่มต้นใน `license.js` ส่วนการตั้งค่า/ใบงานที่ใช้ localStorage อาจอยู่ในพื้นที่เก็บข้อมูล CEP แยกต่างหาก **การสำรองเฉพาะโฟลเดอร์ SignTools ไม่เท่ากับสำรองข้อมูลทั้งหมด** ห้ามล้าง cache/localStorage แบบสุ่มเมื่อมีข้อมูลที่ต้องเก็บ

## รายการก่อนถือว่าจบ rollback

- [ ] ตรวจเลขรุ่นสูงสุดบนเซิร์ฟเวอร์และเครื่องทดสอบแล้ว ไม่ใช้บันทึกเก่าแทน
- [ ] สคริปต์ตรวจทุกไฟล์ของ ZIP และตัวจำลองผ่าน พร้อมเก็บ SHA-256
- [ ] เก็บโค้ดสคริปต์ คู่มือ และเทสต์ใน Git/ที่สำรองถาวรแล้ว
- [ ] หากปล่อย: ช่องเบต้าและกลุ่มทดสอบถูกต้อง รุ่นลูกค้าไม่เปลี่ยน
- [ ] เจ้าของลองปุ่ม ② และงานตัดจริงแล้ว แจ้งผลผ่านก่อนเริ่มข้อถัดไป

การติ๊กว่าผ่านต้องอาศัยสิ่งที่ทำจริง ไม่มีขั้นตอนใดให้ถือว่าผ่านแทนเครื่องจริงโดยอัตโนมัติ
