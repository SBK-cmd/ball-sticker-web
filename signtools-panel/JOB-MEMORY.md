# ใบงานจำข้อมูลผลิต — งานข้อ 1

พัฒนาบนฐานโค้ด 1.13.48 (`eb32bcd`) พร้อมระบบ rollback ที่เตรียมไว้ ไม่ใช้โค้ด 1.13.49–1.13.57 ไม่แก้ `sticker.js`, `host.jsx` หรือตัวสร้างคำสั่ง Graphtec `cutjob.js`

## ข้อมูลที่จำกับใบงาน

คิวอ่าน/บันทึกข้อมูลผลิตเป็น JSON ในฟิลด์ `stProduction` ของ Firestore `jobs/{id}` สำหรับใบราคาส่งเก็บใน `wholesale/{id}.stq.i<รายการ>.stProduction` แยกแต่ละรายการ ไม่เปลี่ยน schema หรือ deploy Worker

ข้อมูลประกอบด้วยเลขใบงานปัจจุบัน, ไฟล์ตัดหลายไฟล์, ไฟล์พิมพ์, พิกัด Bezier ของเส้น Kiss Cut/Die Cut จาก `st_cutRead`, มาร์คจริง/กรอบ artboard สำหรับพรีวิว, ค่าแรง/ความเร็ว/อัตราเร่งแต่ละชนิด และตัวเลือกตัด เช่นภาษา GP-GL/HP-GL, step, หมุน, mirror, overcut, ใช้มาร์ค, condition, ลำดับตัด และจำนวนชุด/ระยะห่างกรณีไม่อ่านมาร์ค

พิกัดและมาร์คเก็บตามที่ host ส่ง ไม่แปลงเป็นจุดเส้นตรงหรือเดาตำแหน่งใหม่ การสแกนใหม่แทน snapshot ทั้งชุด มาร์คและสถานะส่งของสแกนเก่าต้องไม่ค้าง

## วิธีใช้

1. เปิดคิวใบงานจากแอปร้าน สำหรับใบงานเก่าที่เคยผูกไฟล์แล้ว ระบบยังอ่าน `aiFiles`/`aiFile` ได้ หากยังไม่มีข้อมูลผลิต ต้องสแกนและบันทึกครั้งแรกหนึ่งครั้ง
2. ตั้งค่าตัดในหน้า “ส่งตัด” ให้ครบ แล้วกด “สแกนตัด” ของไฟล์ ระบบเก็บเส้น/มาร์ค/ค่าตัดไว้กับใบงานบนคลาวด์โดยยังไม่ส่งเครื่อง ถ้ามีหลายไฟล์ ตั้ง/สแกนแยกแต่ละไฟล์ได้
3. เปิดรายละเอียดใบงานและกด “+ จำไฟล์พิมพ์” เพื่อแนบไฟล์พิมพ์ครั้งแรก ไฟล์พิมพ์จากข้อมูลแอป `printFiles` และจาก `stProduction` ถูกอ่านกลับได้ด้วย ไม่เดาจับคู่หลายไฟล์พิมพ์กับหลายไฟล์ตัด
4. หลังบันทึกสำเร็จ เปิด/รีเฟรชใบงานซ้ำหรือโหลดบนแผงอีกเครื่องจะมีไฟล์ เส้นตัด มาร์คและค่าตัดครบโดยไม่ต้องผูก/สแกนใหม่ การแก้เลข/ข้อมูลทั่วไปของใบเดียวกันจากแอปแล้วบันทึกแบบ merge ต้องไม่ทำให้ข้อมูลผลิตหาย
5. เปิดพรีวิวแล้วแก้แรง/ความเร็ว ค่าใหม่ถูกบันทึกกับไฟล์ของใบงานนั้น ก่อนส่งจะคืนค่าของใบงานนั้น ไม่ใช้ค่าแรงจากใบงานก่อนหน้า

**ใบใหม่ที่แอปยังไม่ได้ให้ไฟล์หรือข้อมูลผลิตมา ไม่สามารถรู้ไฟล์ที่ต้องใช้เองได้** ต้องระบุครั้งแรก ระบบนี้ไม่ค้นหา/เดาไฟล์จากชื่อรายการ และยังไม่ได้เพิ่มช่องกรอกไฟล์/ค่าตัดให้ฟอร์มบนเว็บไซต์แอปจริง ข้อมูลที่มีแล้วในใบงานจะถูกโหลดกลับครบ การค้นหาไฟล์ย้ายที่อยู่ในงานข้อ 2 แยกต่างหาก

## เมื่อบันทึกไม่สำเร็จ

หากคลาวด์ไม่ตอบ ข้อมูลสแกนใหม่ยังเก็บไว้ในแผงและขึ้นคำเตือน “ข้อมูลล่าสุดยังอยู่เฉพาะเครื่องนี้” ให้กด “บันทึกใบงาน” เพื่อลองใหม่ ระบบไม่อ้างว่าซิงก์สำเร็จ และไม่ส่งตัดจากข้อมูลที่ยังไม่ได้บันทึกกับใบงาน

ค่าความเร็วต้องเป็นจำนวนเต็ม 1–100, แรง 1–60 และอัตราเร่ง 1–3 ค่าผิดหรือข้อมูลไม่ครบไม่ถูกเขียนทับด้วยค่าเริ่มต้น/ค่าของใบก่อนหน้า หากข้อมูลผลิตเสียหรือใช้ schema ที่ไม่รองรับ จะแจ้งและไม่โหลดเส้นตัดไปส่งเครื่อง

จำกัด JSON ข้อมูลผลิตที่ 650,000 ไบต์ UTF-8 เพื่อเหลือพื้นที่ข้อมูลทั่วไปในเอกสาร Firestore ใบที่มีพิกัด/ไฟล์จำนวนมากอาจเกินขีดจำกัดและบันทึกไม่ได้ ระบบจะแจ้ง ไม่ตัดพิกัดทิ้งให้เงียบ ๆ และยังไม่ได้ทดสอบขนาดใบงานจริงของร้าน

## ทดสอบออฟไลน์

ต้องมี Node.js 18+; dependency `jsdom` อยู่ในโฟลเดอร์เทสต์เท่านั้น ไม่ถูกบรรจุใน ZIP แผง:

```bash
cd signtools-panel/tests
npm ci
node job-memory-test.cjs
node queue-memory-test.cjs ..
node panel-smoke.cjs .. 1.13.60
```

ตัวจำลองรันโค้ด `queue.js`, `cut.js`, `cutjob.js`, `job-memory.js`, `pack.js` และ `sticker.js` จริง แต่ DOM/Canvas/CEP, Firestore และ LAN เครื่องตัดเป็น mock ไม่มีคำสั่งถูกส่งไปยังเครื่องจริง

## การย้อนกลับ

หากเบต้าที่เตรียมเลข 1.13.60 มีปัญหา ให้ใช้ฐานเสถียร 1.13.48 ด้วยเลขที่สูงกว่าทุกเครื่อง/รุ่นที่ปล่อยอยู่ เช่น:

```bash
cd signtools-panel
bash rollback.sh 1.13.61 --current 1.13.60
```

ตัวอย่างนี้ใช้ได้เฉพาะเมื่อไม่มีเลขสูงกว่า 1.13.60 แล้ว ต้องตรวจหน้า admin/เครื่องจริงก่อนปล่อย และปล่อยเฉพาะเบต้าเท่านั้น ข้อมูล `stProduction` บน Firestore ไม่ถูกลบทิ้งเมื่อถอยแผง แต่แผงฐาน 1.13.48 จะยังไม่อ่านข้อมูลใหม่นี้ ต้องเก็บสำเนาข้อมูลแผงเดิมก่อนติดตั้งเพื่อรักษาคิวเฉพาะเครื่องด้วย

## ให้เจ้าของตรวจหลังติดตั้งเบต้า

- ปิด Illustrator ทั้งโปรแกรมแล้วเปิดใหม่ ตรวจเลขรุ่น
- ลองปุ่ม ① และ **② สร้างแผ่นงาน** ด้วยสำเนางานเล็กก่อน
- ใช้ใบงานทดสอบผูกไฟล์ตัดสองไฟล์ ตั้งแรงต่างกันแล้วสแกน ตรวจว่าแต่ละไฟล์จำค่าแยกกัน
- แนบไฟล์พิมพ์ ปิด/เปิดแผงและรีเฟรชใบงาน ตรวจไฟล์ เส้น Kiss/Die มาร์คและค่าตัด
- แก้ข้อมูลทั่วไปของใบเดิมในแอป บันทึกแล้วโหลดคิวใหม่ ข้อมูลผลิตต้องไม่หาย ไม่ต้องผูกไฟล์ใหม่
- ตรวจค่าตัดที่แสดงก่อนส่ง และตัดเศษวัสดุจริง ตรวจมาร์ค ตำแหน่ง Kiss/Die และแรงตัด
- ถ้าขั้นไหนไม่ผ่าน ให้หยุดและแจ้งอาการ ใช้ระบบ rollback เมื่อจำเป็น

ยังไม่ทดสอบ Illustrator/ExtendScript, ตัวติดตั้ง Windows/macOS, Firestore ของร้าน หรือ Graphtec/NAS จริง และยังไม่ทำงานข้อ 2–6 (หาไฟล์ย้ายที่, QR, รีโมทสั่งตัด/สถานะ/ซิงก์แรงสองทาง)
